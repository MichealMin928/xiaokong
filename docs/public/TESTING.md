# 如何提供有用的测试结果

每次记录版本、机型、Android 版本、语音模式、左右手、距离、光线/背景音和尝试次数。不要提供设备序列号。先在不涉及付款、发送或删除的页面测试。

## 十分钟入门

1. 安静环境，直接模式说“回到桌面”“返回”“显示按钮”，各 5 次；记录听到次数、实际执行次数。
2. 在可滚动列表连续说 10 次“上滑”，每句稍停。记录首次和之后是否有差异、是否到达边界。
3. 显示按钮后点不同编号；翻页后重新编号。确认点中的是标出的真实控件。
4. 四指朝上上移、两指朝上下移各 5 次；收手时检查有没有反方向操作。
5. 食指移动到目标后，拇指靠近两次，左右手各 5 次。记录卡顿、光标偏移、漏点和误点。
6. 结束控制并锁屏，观察相机/麦克风系统指示是否结束。

请分别报告成功数/尝试数、额外误触数和失败现象，不把动作回执等同于页面已经变化。无法完成的步骤写“未测试”。

## 背景音与功耗

先做安静基线，再播放视频或音乐重复同一组指令。记录外放音量档位、媒体是否在说话时被压低、没有发指令时是否误触；不上传版权音视频或私人对话。

长时间测试可分 30 / 60 分钟：相同亮度和网络状态，分别测空闲、仅语音、语音加手势，记录电量变化、温度、是否降帧和中断。不要用这一次结果推断所有设备的续航。

## 自动检查范围

公开 CI 运行通用 JVM 测试、Android Lint、模型校验和 Release 构建。测试涵盖时序、手势互斥、瞄准锁定、声音边界、重复命令、选择失效和生命周期状态；这些不能证明真人准确率、真实无障碍点击成功率或长期热表现。

内部历史采集样本和原始系统证据不公开；不将其计入新参与者可复现的公共测试数量。模拟器截图只展示界面，不作为手机手势/声音验收。
